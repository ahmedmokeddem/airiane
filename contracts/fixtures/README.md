# Shared fictional fixtures

Each JSON file wraps a canonical OpenAPI payload in `{schema, fictional, data}`. Only `data` belongs on the wire. Validate with `python scripts/check_contracts.py` from the repository root in the backend development environment. These examples are not provider responses or real patient records.

The recommendation, activity session, feedback, Journey item, and report reference the same activity/version and resource IDs. Applications may generate fresh UUIDs/times for interactive mocked writes; those responses must retain the same schema and relationship rules. Report data is a fixed fictional example, not a report generated by the current backend.

OpenAPI and tool contracts remain authoritative. Agree any contract change across all four owners before changing consumers. The six-tool contract is broader than the first implemented slice; unsupported tools must fail explicitly, never fabricate success.
